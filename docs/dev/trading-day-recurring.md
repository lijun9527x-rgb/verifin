# 交易日定投

## 使用

在「周期记账」新增规则，类型选「转账」，转出选银行卡的活期资产，转入选对应基金资产，输入每次定投金额，频率选「每个A股交易日」。新规则默认明天开始，也可明确选择其他日期；已有资产应作为起点，避免把余额中已包含的定投再次补记。

打开应用或回前台时补齐到今天的交易日。转账减少活期、增加基金，不作为消费支出；同币种转账不改变总资产。它只记账，不执行真实扣款或基金申购。基金收益仍需手动更新当前金额；历史月份仍由用户核对保存快照。

规则列表显示已缓存年份及下一次日期，顶部同步按钮可强制刷新日历并补记。规则右侧「跳过下一次」确认后只推进这一次，不产生交易；已产生的错误记录可以删除，已记或跳过日期不会重新补记。日历未就绪时显示暂停状态。

## 数据与时机

- 交易日期按北京时间，周六日始终关闭，包括调休补班日。其他周期频率沿用本地日历语义。
- 深交所公开接口为 `https://www.szse.cn/api/report/exchange/onepersistenthour/monthList?month=yyyy-MM`，读取 `jyrq` 日期与 `jybz` 交易标记（`1`/`0`）。首次按年请求十二个月，之后覆盖完整的年份不自动联网；开屏遇缺失年份自动拉取。失败在本会话节流五分钟，手动同步可重试。
- 年份须具备全部有效日期、无重复、无周末开市，全年开市数量须在合理范围（180–270）内。此校验用于拒绝缺月、格式错误或明显未公布的数据，不能取代交易所公告的权威性。接口更新不会改动已生成的交易。
- 年历在应用私有目录以版本化 JSON 缓存，原子替换，损坏可重新下载，不进入账目备份。请求仅携带月份，不附带资产、金额、账户、交易或身份数据。失败保留旧缓存，日志只记年份和错误类型。
- `RecurringFrequency.aShareTradingDay` 和规则的 `handledDates` 日期集合随 SQLite 与 JSON 备份往返。SQLite v22 仅向 `recurring_rules` 添加 `handled_dates`，默认空集合；不修改账户、期初余额、外币手填人民币或月度快照。
- 生成交易与推进规则/回执由 `saveRecurringGeneration` 同一事务提交。并发补记串行执行，持久化失败不发布新的内存状态；删除交易不会删除回执。
- 缺失日期即停止，不把未知年份当周一至周五；单次最多扫描 400 天，跨多年最多拉五个连续起始年份及当前年，后续补记继续推进。没有后台定时扣款或精准时刻保证。

## 节假日来源的适用范围

[holiday 的 Workers 分支](https://github.com/Haoshenqi0123/holiday/tree/cloudflare-workers) 从百度获取年度法定节假日与补班日，使用内存与 Workers KV 缓存；其 `statusOf` 返回普通工作日、周末、补班、节假日，`/holiday?date=yyyy` 无年度数据时返回空数组。`today/tomorrow` 文字接口在缺数据时会按普通周末规则降级，不能用于本功能的自动落账依据。

它可以作为未来自建服务的缓存和负缓存参考，但法定工作日不等于交易日。例如交易所可能在法定假期外另行休市，周末补班也不交易。本版本不部署该服务，也不把它直接作为自动替代源；将来要接入，须在完整节假日上叠加经核实的交易所特别休市安排并校验覆盖范围。

## 验证

`test/trading_calendar_test.dart` 覆盖年度缓存、并发拉取、跨年、错误格式、损坏缓存、北京时间边界、开始日期、跳过/删除/重启去重、两端余额、资产及快照保护、SQLite v21 升级及新增频率菜单。现有周期规则、迁移矩阵与中英文键守卫继续适用。Android 需安装升级包，验证真实网络、进程重启缓存与回前台补记；不得清除应用数据。
